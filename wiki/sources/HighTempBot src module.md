## Module map

Modules are grouped by concern. Each entry links to the dedicated wiki concept page (in double brackets) where one exists, plus the file path in the runtime tree.

### Entry & boot

- `main.py` (Startup Sequence) — `python -m hightempbot.main`. Builds Config, opens WAL DB, runs **fee-adjusted PnL backfill**, **dry-run cancel on live restart** (`_stop_dry_run_pending_for_live`), **runtime mode sync** (`_sync_station_runtime_mode`), **resolved-actual backfill**, **bracket-bounds migration** (one-shot integer→float fix on `market_tokens`), **auto-retrain missing calibration**, registers all stations, schedules jobs (20-thread executor), launches FastAPI dashboard in a thread.
- `runtime_config.py` — Pydantic `BaseSettings` from `.env`. SecretStr fields: `poly_private_key`, `poly_api_key`, `poly_secret`, `poly_passphrase`, `relayer_api_key`, `notify_telegram_token`. Public: `poly_signature_type`, `poly_funder`, `relayer_url`, `relayer_api_key_address`, `wu_api_key`, `dry_run`, `initial_bankroll`, `db_path`, `dashboard_port/user/pass`, `notify_telegram_chat_id`. Frozen — `dry_run` flips happen on a local var, never on `cfg`.
- `stations.py` — `StationConfig` frozen dataclass + `STATIONS: dict[str, StationConfig]` runtime registry (populated from `enrolled_stations` table at boot). `ICAO_TO_CITY` rebuilt by `register_enrolled_station`. Conversion helpers `fahrenheit_to_celsius` / `celsius_to_fahrenheit`. `SUPPORTED_LIVE_SOURCES = {"wu"}` — only WU stations get live actuals/scans; HKO etc. are forecast-trained but skipped at runtime.

### Calibration

- `calibration/emos.py` ([[EMOS Calibration]]) — `fit_emos`, `predict_emos`, `emos_probability`. NGR with `mu = a + b·ens_mean`, `sigma² = exp(c) + exp(d)·ens_var`. CRPS-minimised via L-BFGS-B; sigma floor `0.1°C`.
- `calibration/lut.py` ([[Walk-forward LUT]]) — `BUCKETS` 8-grid, `bucket_of`, `lookup`, `lookup_with_cumulative` (strict `local_date < asof`), `rebuild_lut`, `append_triples_for_date`, `seed_lut_from_history`, `stamp_refreshed`. Walk-forward EMOS memoized via `_walk_forward_params` ↔ `calibration_params_history`.
- `calibration/model.py` (Forecast Model) — `CalibrationModel.predict(ensemble, threshold)` + `retrain(station, horizon, conn)`. Ensemble-size filter pins to most common count.
- `calibration/monthly_retrain.py` (Monthly Retrain) — `run_monthly_retrain` backfills last month, retrains EMOS, calls `refresh_lut_after_retrain` (rebuild if rows exist, else seed from history).
- `calibration/store.py` (Calibration Store) — JSON `params_blob` to `calibration_params` (current) and `calibration_params_history` (walk-forward by `asof_date`).

### DB

- `db/connection.py` (DB Schema) — `get_connection` (WAL + `synchronous=NORMAL` + `foreign_keys=ON`); `init_db` runs a pre-schema compatibility migration for legacy `operator_control_state.version`, then `schema.sql`, then `_migrate_db`. Migrations: drops legacy `signals.gate_entropy/gate_circuit_breaker`, drops `enrolled_stations.promoted_at`, adds ledger forensics columns (`realized_edge`, `prob_safe_floor`, `pred_bucket_low/high`, `n_bucket`, `transaction_hash`, `verify_attempts`, `verification_downgraded`), drops retired `lcb`/`ucb`, rebuilds `bss_scores` if legacy `month` column present, plus `_migrate_pred_bucket_history` (bucket-key→bracket-key uniqueness fix that wipes `lut_bucket_stats` to force reseeding). Schema now includes live-operator/readiness/wallet audit tables: `operator_control_state/events`, `live_readiness_reports`, `transfer_requests`, `redemption_requests`, and `wallet_reconciliation_*`.

### Enrollment

- `enrollment/pipeline.py` (Station Enrollment) — `enroll_station` 8-step state machine: parse → existing-row recovery → geocode → backfill actuals (skip-forward by 365d up to 3 times if early years return nothing; abort after 30 consecutive failures with data) → coverage gate (`MIN_COVERAGE_PCT=0.95`) → backfill forecasts → train EMOS for h=1/2/3 → seed LUT (`_seed_market_tokens_from_event` first so LUT has brackets) → transition to `DRY_RUN` or `LIVE`. Retryable skip reasons: `low_bss`, `train_failed`, `lut_seed_failed`, `insufficient_lut_data`, `low_coverage` (after enough actuals), `unknown_source` / `unsupported_source` (when source becomes supported).
- `enrollment/parser.py` (Geocoding & Enrollment Parser) — Tier 1 WU URL (`wunderground.com/weather/.../ICAO`), Tier 2 HKO description fallback (`hong kong observatory` / `weather.gov.hk`), unit inferred from market questions (`°F` / `°C`) then description, US/CA/MX/PA ICAO prefixes force `unit=F`.
- `enrollment/geocode.py` — Open-Meteo `geocoding-api/v1/search`. In-memory cache keyed by lower-cased city. Retries 3× with exp backoff; HTTP 200 + empty results = genuinely not found, do not cache the negative.

### Execution

- `execution/types.py` — `BetSignal`, `OrderResult`, `CycleResult`. `BetSignal.entry_top_price` is the scanner-time top-of-book anchor for retry walks and sticky slot identity. `BetSignal.entry_fill_vwap` records the decision-time book-walked VWAP of this fill in `event_detail.entry_fill_vwap`; `slot_state` can read the earliest non-cancelled row's value back. `slip_anchor_vwap` remains in-tick-only plumbing for any sleeve with a configured top-up slip cap; active NO/TAIL set that config to `None`.
- `execution/strategy_constants.py` — sizing constants (`MIN_BET_USD=1.0`, `MAX_DD=0.40` full halt, `MAX_DAILY_NOTIONAL_FRAC=1.00`, `MAX_PENDING_EXPOSURE_PCT=1.00`; `MAX_BET_CAPITAL_FRAC` removed — per-sleeve `capital_frac` is the sole sizing dial), fee `POLY_FEE_THETA=0.05`, `RELIABILITY_CALIBRATION_ENABLED=True` + `ALLOWED_BRACKET_UNITS={F,C}` (2026-07-16 calibrated gate; the legacy single-gate globals `NO_MIN_FILL_PRICE`/`YES_MIN_FILL_PRICE`/`YES_MIN_EDGE`/`YES_MAX_EDGE`/`BET_SIDES` are removed), LUT (`LUT_STALE_HOURS=36`, `MIN_PAIRS=30`), retry constants (`MAX_ORDER_RETRIES=3`, `VERIFY_POLY_TIMEOUT_S=15`), cadence (`SCAN_INTERVAL_MINUTES=10`, `BETTING_LOCAL_CUTOFF_HOUR=0`, `RESOLUTION_SCAN_START_HOUR=18`), `WU_CONSENSUS_MODE="OFF"` (hardcoded, not env-overridable), `DASHBOARD_SESSION_START_UTC="2026-08-09 00:00:00"` (FLIP-experiment session reset), `EXPECTED_MODELS` (9), `RESOLUTION_PRICE_THRESHOLD=0.995` / `RESOLUTION_LOSS_PRICE_THRESHOLD=0.005`, `EARLY_RESOLUTION_ENABLED=False` (CLOB threshold settlement off since 2026-05-22; production settles via Gamma close-state), `POLYMARKET_FALLBACK_DAYS=1` (floor for the MANUAL WU fallback — auto-fallback is disabled). **Active strategy = the L2-depth base + 2026-07-16/17 calibrated NO gate + 2026-08-09 FLIP experiment**; `backtest/configs/candidate_l2_depth.json` remains the L2-base source of truth and `tests/test_strategy_constants.py` guards the ported values. `STRATEGY_CONFIGS` registry (five `StrategyConfig` sleeves — NO/YMID/TAIL/YHIGH/FLIP; only NO **or** FLIP can fire, swapped at boot by `_apply_flip_mode` when `FLIP_MODE=1`):
  - **NO** — `p_E`, `fp_min=0.75`, `min_edge=0.05` (0.090 → 0.04 on 07-16, → 0.05 on 07-17; edge computed on the reliability-calibrated claim), `max_edge=0.15`, hours [0..6], `capital_frac=0.07`, `execution_min_edge=0.05`, `max_vwap_slip_from_anchor=None`; ceiling extension `signal=p_B_50/fp_min=0.50/max_edge=0.35`; holds to resolution. Boot-disabled while FLIP_MODE is on.
  - **FLIP** — operator experiment (2026-08-09, measured −EV): buys YES on exactly the brackets where the NO gate fires (`p_E_flip`, gate re-evaluated in `_evaluate_flip_branch`), `capital_frac=0.07`, `min_edge=-1.0` intentional (sole fill leash = `max_walk_price` ask+0.05, `execution_min_edge=None`), fp band 0.01..0.50, hours [0..6], holds to resolution. `enabled=False` at rest; boot-toggled on by `FLIP_MODE=1`.
  - **TAIL** — **`enabled=False` since 2026-07-17** (EV≤0 at honest fills; the dump-to-2c delayed-entry trigger is the adverse selection; L2 TAIL profit was a fill artifact). Tuned params stay for rollback: `tail_vote_avg` 4-of-4 over `(p_E, p_B_50, p_L_loose, p_Shrink_n10)`, `alpha=4.0`, signal `fp=0.001..0.03`, `delayed_entry_fp_max=0.02`, `entry_hour_set={1}`, `capital_frac=0.05`, `execution_min_edge=0.07`, `tp=0.20`, `consensus_skip_threshold=0.40`.
  - **YMID / YHIGH** — `enabled=False` (documented but never fire).
  Sizing is per-strategy `capital_frac` with idempotent top-up; there is no static stake cap. `max_vwap_slip_from_anchor=None` means top-ups recheck current gates and rely on the realized VWAP edge floor instead of first-fill VWAP + cap. (Renamed from `execution/config.py` in U16.)
- `execution/capital.py` (Capital Snapshot) — `get_capital_snapshot` returns `CapitalSnapshot(realized_pnl, pending_exposure, realized_capital, deployable_capital, peak_realized_capital)`. Live bets only — dry-run rows are excluded from drawdown and sizing.
- `execution/live_readiness.py` — shared GO/NO-GO checks for live trading: env shape, signer/proxy/deposit-wallet topology, relayer settings, CLOB credentials, Polygon RPC/pUSD reads, and report persistence to `live_readiness_reports`. Used by startup, Operator dashboard, `cli/live_go_no_go.py`, and env-parity tooling.
- `execution/operator_control.py` (FastAPI HTMX Dashboard) — durable SQLite Stop Processing / Start Processing / Transfer Lock state with optimistic `version` updates, public payload shaping, mid-tick processing blockers, and audit-table pruning for operator/readiness/wallet/transfer/redemption tables.
- `execution/polymarket_transfer.py` — safe pUSD return-transfer preview/submit helper. Requires Transfer Lock, fresh readiness, complete warning-free wallet snapshot, no open CLOB orders, no local in-flight PENDING rows, exact generated confirmation, and amount bounded by free pUSD.
- `execution/polymarket_relayer.py` — thin relayer client used for deposit-wallet transaction submission.
- `execution/polymarket_redeemer.py` (Polymarket Resolution) — live-only Data API redeemable-position scanner. Matches redeemable wallet positions to local bot ledger rows, records `polymarket_data_api_redeemable` WIN resolutions for matched PENDING rows, persists `redemption_requests`, and submits at most one relayer redemption per scan.
- `execution/walker.py` ([[Edge-Preserving Sizing]]) — `walk_book_edge_preserving` with NaN-safe inputs and `walk_anchor_price` for sticky retry caps. `OrderClient.place_order` (FAK BUY) and `close_position` (FOK SELL at bid VWAP). `execute_or_log` 3-path (legacy 1-retry / dry-run walked / full-feature FAK submit with same-order verification, partial-fill actual notional, and `verification_downgraded` ledger audit when tx hash lags). `_clob_executor = ThreadPoolExecutor(max_workers=16)`. Validates `POLY_1271` deposit-wallet order shape before posting (`signatureType=3`, `maker == signer == POLY_FUNDER`, ERC-1271 wrapped signature) and treats deposit-wallet/proxy auth errors as terminal `auth` failures. **L2 champion + 2026-05-31 overrides:** `signal.slip_anchor_vwap` remains optional plumbing for sleeves with a configured VWAP-slip leash, but active NO/TAIL set `max_vwap_slip_from_anchor=None`; order-time re-walks are bounded by the realized edge floor. A NULL-anchor transition slot falls back to the edge floor rather than re-anchoring to the drifted live top; `_sorted_asks`/`_sorted_bids` hardened against a book missing a side (coerce `None`→`[]`). (Renamed from `execution/order.py` in U16.)
- `execution/pipeline.py` (Betting Pipeline) — `run_betting_cycle` orchestrator: coverage gate → capital snapshot → **drawdown halt at MAX_DD=0.40** (changed from "halve" to "halt" on 2026-05-20) → pending-exposure cap → wallet balance gate (live only, `<$5` hard skip, capital divergence warning at >10%) → ensemble exact-set check → load EMOS → `evaluate_station` → log skips immediately, log passes after execution → `record_bet` PENDING then `execute_or_log`.
- `execution/tp_sl_monitor.py` (TP/SL Monitor) — per-strategy TP/SL ticker for `YMID` (TP=0.15) and `TAIL` (TP=0.20). `_set_close_in_flight` flag + `TP_SL_FLAG_STALE_SECONDS=600` age-out + 3× retry on ledger write after successful close (with `orphan_close` marker fallback if record_position_close keeps raising). Reasons stamped: `ymid_tp` / `tail_tp` (live) and `..._dry` (dry-run).
- `execution/notify.py` (Telegram Alerts) — `send_alert(title, message, config, stage, station_id)` rate-limited 15min per `event_type:station_id`; lifecycle events (`station_discovered/enrolled/promoted/paused`) skip rate limiting. Telegram only — webhook stub kept but unused.

### Decision

Split out of `execution/` in U13 to give the gate stack its own package alongside calibration and execution.

- `decision/strategies.py` ([[Signal Flavors (live)]]) — `evaluate_station` runs each Polymarket bracket through `_evaluate_strategy` for every sleeve in the 5-entry registry; disabled sleeves (TAIL/YMID/YHIGH, plus whichever of NO/FLIP the FLIP_MODE boot swap turned off) never fire. NO uses `_evaluate_no_branch` (strict gate + ceiling-bracket relaxation with `signal_name_for_ceiling=p_B_50` + `fp_min_for_ceiling=0.50`); since 2026-07-16 the claimed NO probability is passed through the reliability-calibration layer (`calibration/reliability.py`, `logit_blend` per NO_C/NO_F) before the edge/fee math, and `prob_safe_floor` records the calibrated claim. Cold-start guard (`n_cum < LUT_MIN_N_FOR_SHRINKAGE=30`) emits SKIP signals. Top-ups recheck current gates and walk until the realized VWAP edge floor would break. `rank_signals` enforces target-date notional cap on top of per-strategy passes. (Moved from `execution/decision.py` in U13.)
- `decision/brackets.py` (Bracket Math) — `build_brackets` 11-bracket ladder centered on ensemble median (2°F US / 1°C non-US). `bracket_probabilities` computes the calibrated probability per bracket from the EMOS Gaussian; warns when sum is outside `[0.95, 1.05]`. (Moved from `execution/brackets.py` in U13.)

- `ingestion/polymarket_prices.py` (Polymarket Price Ingestion) — the scraper half is **retired**: the `polymarket_prices` / `polymarket_price_history` tables are legacy (they were written by a removed external cron; per-tick order-book telemetry now lands in `book_snapshots`, written by `betting_tick._persist_book_snapshots` with 180d retention). The module survives as a helper library — `GAMMA_API`, `gamma_event_slug` (slug `highest-temperature-in-{city}-on-{month}-{day}-{year}`), `_CITY_TO_ICAO` — imported by `resolution/gamma.py`, `scheduler/market_data.py`, `scheduler/jobs.py`, and `stations.py`.

- `ingestion/sources/wu.py` — actuals scraper. `_ICAO_COUNTRY` 30-row prefix table for the `ICAO:9:COUNTRY` URL form. `_MIN_DELAY_S=0.5` per-worker (10×0.5s safe; 27×0.3s causes SSL EOF). Cached per `(icao, date, unit)` JSON file under `data/wu_cache/`.

### Scheduler

- `scheduler/jobs.py` (Scheduler Jobs) — `schedule_all_jobs`: per-station midnight actuals (`00:05` local), betting + resolution scans (every 10 min, station-local timezone, deterministic ICAO-derived 0–9 minute offset to spread thunder-herd), TP/SL monitor (10-min cadence offset 5m from betting tick), live-only wallet snapshot refresh (default every 10 min), live-only auto-redeemer (default every 10 min, one redemption submit per scan), monthly housekeeping (1st 02:00Z), monthly historical retrain (1st 03:00Z), weekly forecast backfill (Sun 05:00Z), daily periodic retrain (04:00Z, 30-day stale gate, 120s/station timeout), 6-hourly enrollment scan, 15-min system health check. `EVENT_JOB_ERROR` listener logs failed jobs prominently. Module also exposes `materialize_actual_tmax_into_ledger(conn, station_id, target_date, tmax_celsius, source)` — called inline by `scrape_actuals_job` after a successful WU scrape to UPDATE any resolved ledger row for that (station, date) where `actual_tmax IS NULL`. Closes the asymmetry between the Polymarket Resolution write path (which writes at resolution time for WIN/LOSS/PUSH) and CLOSED rows from TAIL TP-exit (which close intraday before the daily high is observable). Gated on `source IN SUPPORTED_LIVE_SOURCES`, idempotent. Added 2026-05-20.
- `scheduler/station_scanner.py` (Station Scanner) — shared scanner utils + `_notify` re-export. UTC ensemble-readiness probe via Open-Meteo `meta.json` per `_META_PROBE` map (cached per UTC date with 5-min retry while waiting). `_target_date_for_ready_cycle` computes target date from per-station UTC cycle, never from `forecast_archive` which can be poisoned by other-station backfills. Negative-event cache `_NEGATIVE_MARKET_CACHE_TTL=6h`, positive cache `12h`. (Slimmed in U16: per-tick code moved out to `betting_tick`, market fetchers to `market_data`, healing helpers to `station_healing`, settlement tick to `resolution/settler.py`.)
- `scheduler/betting_tick.py` — `run_betting_tick` per-station: gate sequence + market/ensemble fetch + `run_betting_cycle` dispatch. Split out of `station_scanner.py` in U16.
- `scheduler/market_data.py` — Gamma + CLOB fetchers (`/price` → `/book` fallback, `volume24hr` by `conditionId`, `_filter_tradable_markets`, `market_tokens` cache writes). Split out of `station_scanner.py` in U16.
- `scheduler/station_healing.py` — station-unit auto-heal + late-enrollment LUT bootstrap helpers. Split out of `station_scanner.py` in U16.

### CLI

Argparse-level validation for `--target-date` (ISO YYYY-MM-DD, not future) and `--station` (4-char ICAO, uppercased). `PRAGMA busy_timeout=5000` so a concurrent scheduler tick doesn't strand the operator with `SQLITE_BUSY` mid-loop. Shares the `_resolve_via_wu_actual_fallback` and `preview_wu_fallback_outcome` helpers with the `/api/v2/admin/resolve-pending` endpoint so commit and dry-run behavior can't drift between CLI and HTTP.

## Cross-cutting invariants enforced inline

- **Per-thread sqlite** — every scheduled job opens its own `get_connection(db_path)` and closes in a `try/finally`. WAL mode set in `db/connection.py:23`; `check_same_thread=False`.
- **Live-mode cancel of dry-run PENDING** — `main._stop_dry_run_pending_for_live` flips `event_type='dry_run' AND outcome='PENDING'` → `CANCELLED` so the simulated book doesn't double-occupy capacity ([main.py:77-93](../../src/hightempbot/main.py#L77-L93)).
- **Live Polymarket wallet topology** — current account must use `POLY_SIGNATURE_TYPE=3` + deposit wallet `0xFf4eCB28218af1874da6086d30D1f3125fa1c843`; reverting to proxy signature type makes order placement fail even though the proxy balance is visible.
- **Runtime-mode label sync** — `_sync_station_runtime_mode` rewrites `enrolled_stations.status` between `DRY_RUN` and `LIVE` based on `cfg.dry_run` ([main.py:96-124](../../src/hightempbot/main.py#L96-L124)).
- **Bracket-bounds one-shot migration** — startup adjusts pre-fix integer-label `market_tokens` rows by `±0.5°` so post-fix continuous bounds are uniform ([main.py:229-273](../../src/hightempbot/main.py#L229-L273)).
- **Auto-retrain missing calibration** — startup retrains stations that have aligned actuals/forecasts but no `calibration_params` row, then refreshes the LUT ([main.py:35-74](../../src/hightempbot/main.py#L35-L74)).
- **Strategy idempotency with NULL guard** — `_strategy_idempotency_count` matches both `strategy=NEW` AND legacy `strategy IS NULL` rows so cross-deploy duplicate detection survives ([strategies.py ~L242-288](../../src/hightempbot/decision/strategies.py)).
- **Mode-scoped TP/SL queries** — `pending_positions_by_strategy(dry_run=...)` filters `event_type` to prevent cross-mode close attempts on stale dry_run rows ([ledger.py ~L204-251](../../src/hightempbot/persistence/ledger.py)).
- **Edge-preserving walker is fail-closed on non-finite** — NaN/Inf in `prob_safe_floor`/`fee_theta`/`min_edge`/`max_walk_price`/`walk_anchor_price` causes the walker to refuse rather than silently eat a bad book ([walker.py ~L135-156](../../src/hightempbot/execution/walker.py)).
- **Walk anchor stickiness** — `walk_anchor_price=signal.entry_top_price` is still passed on retry/dry-run walker calls for sticky slot identity; active NO/TAIL no longer use that anchor as a top-up slip cap ([walker.py](../../src/hightempbot/execution/walker.py)).
- **Per-strategy walker `min_edge`** — `_min_edge_for_signal` returns the sleeve's `execution_min_edge` when configured (NO 0.05, TAIL 0.07), so retry/dry-run order walks match scanner-time sizing ([walker.py](../../src/hightempbot/execution/walker.py)).
- **Net-of-fees PnL invariant** — both entry and exit fees are deducted in `record_resolution` and `record_position_close`. `backfill_fee_adjusted_pnl` migrates historical rows once and stamps `fee_adjusted_at` to make the migration idempotent ([ledger.py ~L95-142](../../src/hightempbot/persistence/ledger.py)).
- **WU forecast `night.temp` is forbidden** — explicit comment block at [wu_forecast.py:104-138](../../src/hightempbot/ingestion/wu_forecast.py#L104-L138) — fall back ONLY to the daytime daypart, never `night.temp` (overnight low).
- **WU concurrency budget** — `_MIN_DELAY_S=0.5` per worker; documented at [sources/wu.py:36-38](../../src/hightempbot/ingestion/sources/wu.py#L36-L38) (10×0.5s stable, 27×0.3s causes SSL EOF).
- **Ensemble exact-set check** — `run_betting_cycle` hard-skips when the live ensemble's keys don't equal `set(EXPECTED_MODELS)` exactly ([pipeline.py:163-172](../../src/hightempbot/execution/pipeline.py#L163-L172)).
- **Notional cap uses realized capital, not deployable** — `rank_signals(..., capital=realized_capital)` so the daily notional cap doesn't double-subtract pending exposure ([pipeline.py:222-228](../../src/hightempbot/execution/pipeline.py#L222-L228)).
- **Trading window is strict equality** — `local_date != target_date` (both `<` and `>`) skips the betting tick. Earlier one-sided gate left east-of-UTC stations bettable for the wrong target_date ([betting_tick.py ~L268-285](../../src/hightempbot/scheduler/betting_tick.py)).
- **Target date never inferred from `forecast_archive`** — `_target_date_for_ready_cycle` derives target_date from per-station UTC cycle alone. A backfilled or future row from another station can otherwise advance every station to the wrong market date before the per-station ensemble lock runs ([station_scanner.py ~L190-205](../../src/hightempbot/scheduler/station_scanner.py)).
- **Loss confirmation requires executable ask** — A token's "dead" verdict needs `best_ask ≤ RESOLUTION_LOSS_PRICE_THRESHOLD`. A low/missing bid alone is a quote void, not proof; settling on it would mis-resolve LIVE bets when the book temporarily empties ([settler.py ~L882-888](../../src/hightempbot/resolution/settler.py), [~L949-955](../../src/hightempbot/resolution/settler.py)).
- **Polymarket > WU for resolution** — when WU `actual_display` disagrees with the Polymarket-declared bracket, scanner logs `R29 MISMATCH` WARNING but always settles from Polymarket. Single source of truth ([settler.py ~L1022-1032](../../src/hightempbot/resolution/settler.py)).
- **Tradable-CLOB filter before caching market_tokens** — `_filter_tradable_markets` rejects brackets without a live YES or NO order book before the row hits the DB cache. Otherwise dead tokens from Gamma poison the cache for 12h ([market_data.py ~L1522-1545](../../src/hightempbot/scheduler/market_data.py)).
- **Volume24hr matches by `conditionId`, not enumerate index** — Gamma may not return brackets in stable order; index match misaligns volumes to wrong brackets ([market_data.py ~L438-446](../../src/hightempbot/scheduler/market_data.py)).
- **Dashboard cookie scope** — `samesite=strict`, `max_age=7d`, `secure` flag tracks request scheme. Token regenerates at process boot so a restart invalidates all sessions ([app.py:1063-1070](../../src/hightempbot/dashboard/app.py#L1063-L1070)).
- **Dashboard session baseline = bare `initial_bankroll`** — operator regime (2026-05-04): pre-cutover PnL is excluded from every dashboard surface. `conn` arg kept on `_session_baseline_capital` only so a future strategy swap doesn't break the signature ([app.py:252-261](../../src/hightempbot/dashboard/app.py#L252-L261)).
- **Degraded-payload fallback** — `_build_v2_payload` returns a shape-complete envelope with `error`/`errorDetail` when `build_htb_data` raises, so the SPA renders a banner instead of blanking. Cross-cuts `/api/v2/data`, `/api/v2/data.js`, and post-build filters ([app.py:1130-1224](../../src/hightempbot/dashboard/app.py#L1130-L1224)).
- **Dashboard `actual_from_bracket` reads winning bracket** — for resolved rows, the comparison midpoint comes from `event_detail.resolution_bracket_low/high` (winning), not the bet's own bracket. NO bets that won have actuals matching the *opposing* bracket ([app.py:907-932](../../src/hightempbot/dashboard/app.py#L907-L932)).
- **`/api/pnl-data` returns 410 Gone, never redirects** — old shape `{labels, pnl, bets}` is incompatible with `/api/v2/data`; redirect would silently break consumers ([app.py:1266-1286](../../src/hightempbot/dashboard/app.py#L1266-L1286)).
- **Resolved-market gate uses explicit polymarket-source IN list, not LIKE** (since 2026-05-20). The scheduler's "skip this tick, market is resolved" gate at [betting_tick.py:291-322](../../src/hightempbot/scheduler/betting_tick.py#L291-L322) used to filter on `resolution_source LIKE 'polymarket_%'` AND `outcome IN ('WIN','LOSS','PUSH')`. That fired on PUSH accounting downgrades (single bracket NULL fill_price, market still trading), on `polymarket_gamma_closed_bracket` (one losing bracket closed, winning bracket still being pinned), and on `wu_actual_fallback` (local-only resolution Polymarket might still override). Replaced with explicit IN list of the four full-market sources (`polymarket_winner`, `polymarket_terminal_yes`, `polymarket_terminal_token`, `polymarket_gamma_closed`). Mode-aware `event_type` filter: live tick checks `bet` rows only, dry-run checks `dry_run` only — a stale dry_run row from yesterday's staging can't block today's live bets and vice versa.
- **`record_resolution` rowcount discipline** (since 2026-05-20). `record_resolution` returns `bool`; all 6 call sites in [resolution/settler.py](../../src/hightempbot/resolution/settler.py) only `resolved_count += 1` on a `True` return. A concurrent scheduler+operator-CLI race that both call `record_resolution` on the same row used to both increment their local counters and write "Resolved 10/10 bets" to `pipeline_health` twice; now only the actual writer counts.
- **`actual_tmax` materialized at scrape time** (since 2026-05-20). The `00:05` local actuals scrape in [scheduler/jobs.py](../../src/hightempbot/scheduler/jobs.py) calls `materialize_actual_tmax_into_ledger` after writing the WU row — UPDATEs any resolved ledger row for that (station, date) where `actual_tmax IS NULL`. Closes the asymmetry between resolution-time write (WIN/LOSS/PUSH) and CLOSED rows from TAIL TP-exit (which close intraday before the daily high is observable). The dashboard's query-time `COALESCE(l.actual_tmax, a.tmax_celsius)` ([v2_data.py:1073,1092](../../src/hightempbot/dashboard/v2_data.py#L1073)) remains as a safety net but is no longer load-bearing.
